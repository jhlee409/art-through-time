# Art Atlas

로컬 서버를 실행한 뒤 브라우저에서 엽니다.

`Art_through_Time.cmd`를 더블클릭하거나, 아래 명령을 실행합니다.

```powershell
node server.js
```

그런 다음 `http://localhost:4173/?login=1`이 열리고 로그인 화면이 먼저 나타납니다. 관리자 인증을 하거나 건너뛰기를 선택하면 최근에 보던 화면으로 이동합니다. 미술 사조 화면은 왼쪽의 `사조` 버튼이나 `http://localhost:4173/?movementPopup=1`에서 새 창으로 열 수 있습니다.

화가를 처음 선택하면 Wikimedia의 공개 Wikidata 정보를 조회해 작품 제목, 제작 연도, 제작 국가, 화파, 이미지와 설명을 가져옵니다. 결과는 `data/generated/<화가-id>.json`에 저장되어 다음 선택부터는 인터넷을 다시 조회하지 않습니다.

`data/artists.json`이 화가와 작품 목록의 원본 파일입니다. 화면에서 직접 추가한 화가, 작품, 보강된 작품 목록과 화가 이름 옆에 추가한 웹주소 링크는 이 파일에 저장됩니다. 이 파일은 Git 추적 대상이므로 다른 컴퓨터와 공유하려면 변경을 커밋한 뒤 GitHub에 푸시해야 합니다.

기존 버전이나 다른 컴퓨터의 브라우저 저장소에만 남아 있던 목록은 실행 시 `data/artists.json`에 빠진 화가와 작품만 추가하는 방식으로 병합됩니다. 파일에 이미 있는 내용은 브라우저의 오래된 값으로 덮어쓰지 않습니다.

화면에서 직접 추가한 작품은 `origin: "manual"`로 저장됩니다. 이후 작품 목록을 갱신해도 이 작품은 변경하거나 삭제하지 않으며, 갱신은 이전 자동 수집 목록에 있던 작품만 대상으로 합니다. 선택한 화가의 왼쪽 목록 아래 `직접 추가한 작품`에서 ×를 눌러 해당 작품만 삭제할 수 있습니다.

## 관리자와 보기 모드

처음 열 때 관리자 이메일과 비밀번호를 입력하면 추가, 수정, 삭제 내용이 `data/artists.json` 원본에 저장됩니다. 건너뛰기와 `.env` 파일이 없는 실행은 모두 보기 모드입니다.

관리자 모드는 한 세션만 유지됩니다. 새 창에서 다시 관리자로 로그인하면 이전 관리자 세션은 자동으로 정리되고 새 로그인으로 이어집니다. `미술 사조로 보기`의 역사 사건 추가·편집을 포함한 모든 변경 기능은 관리자 모드에서만 사용할 수 있습니다.

## 최신 규칙 점검과 보고서

관리자로 로그인하면 화가 연표, 미술 사조, 미술 기법, 주제-사건 화면의 오른쪽 위에 `전체 규칙 점검` 버튼이 보입니다. 어느 화면에서 실행해도 전체 자료에 같은 점검을 적용합니다.

점검은 최신 작품 정리 규칙과 고해상도 이미지 경로를 적용하고, 이름 사전과 uHangul 화가 맵을 다시 생성합니다. 수동 입력 작품, 직접 작성한 설명·이미지, 사용자가 선택한 대표작은 덮어쓰지 않으며, 외부 웹에서 작품을 다시 수집하거나 삭제하지 않습니다.

점검을 마치면 결과가 화면에 표시되고, 아래 형식의 Markdown 보고서가 자동 저장됩니다.

```text
변경사항/규칙점검_YYYYMMDD_HHMM.md
```

보고서에는 점검 시간, 대상 화가·작품 수, 자동 적용 결과, 이미지 또는 제목이 없는 작품의 화가명·작품명·작품 ID가 기록됩니다. 남은 항목을 수정한 뒤 다시 점검합니다. 다음 작업 세션에서는 이 보고서를 전달하거나 “가장 최근 규칙점검 보고서 확인해줘”라고 요청하면 됩니다.

## 미술 사조 HTML 작성

사조 설명 HTML을 새로 만들거나 보강할 때는 `data/미술사조/WRITING_GUIDE.md` 기준을 따릅니다. 하위 화파, 대표 화가별 대표작 카드, 국가별 전개 설명을 반드시 포함합니다.

## 작업 폴더와 동기화

Git 작업은 OneDrive 밖의 `Documents/Document_backup/Art_through_Time` 폴더에서 합니다. 이 폴더의 코드, 화가·작품 데이터, 생성 JSON, 미술 사조 HTML은 GitHub로 관리합니다.

다음 경로는 OneDrive 데이터 폴더를 직접 가리키도록 연결되어 있으며 Git에는 올리지 않습니다.

- `data/thumbnails/`
- `data/high-resolution/`
- `data/topic-images/`
- `data/backups/`, `data/.image-staging/`, `logs/`
- `delivery/`
- `.env`

따라서 코드·데이터를 변경했으면 `git add`, `git commit`, `git push`를 실행합니다. 이미지, 환경 설정, 로그, 배포 결과물은 위 연결 경로에 저장하면 OneDrive가 자동 동기화하므로 별도로 복사하지 않습니다. 다른 컴퓨터에서는 Git 작업 폴더를 별도로 만들고 같은 OneDrive 경로 연결을 설정해야 합니다.

이번 구성의 상세 이유와 작업 기록은 [`변경사항/변경사항_20260821.md`](변경사항/변경사항_20260821.md)를 참고하세요.
