# uHangul v0.5 specification

## 1. 확장 자음

| Token | 음가 | 표시 자형 | 사용 위치 |
|---|---|---|---|
| F | /f/ | ᅗ형 | 초성만 |
| V | /v/ | ᄫ형 | 초성만 |
| Z | /z/ | ᅀ형 | 초성만 |
| R | /ɹ/ | ᄙ형 | 초성만 |
| TH | /θ/ | θ형 | 초성만 |
| X | /x/ | ᅘ형 | 초성만 |
| CH | /ç/ | ᅙ형 | 초성만 |

**새 자음은 종성으로 절대 사용하지 않는다.**

## 2. 조판 원칙

새 음절을 자소별로 다시 조판하지 않는다.

1. 새 자음에 대응하는 기존 한글 초성을 선택한다.
   - F→ㅍ, V→ㅂ, Z→ㅅ, R→ㄹ, TH→ㅅ, X/CH→ㅎ
2. 해당 초성 + 같은 모음 + 같은 기존 종성의 **완성형 한글 glyph**를 template으로 사용한다.
3. template의 초성 component만 새 자음 vector outline으로 교체한다.
4. 모음, 종성, advance width, baseline, 나머지 component는 원본을 그대로 유지한다.

따라서 `ㅡ`를 포함한 모음 위치와 종성 위치는 원본 한글과 동일하다.

## 3. 코드 공간

SPUA-A `U+F8000–U+F9013`.

```text
codepoint = U+F8000
          + ((new_onset_index × 21 + vowel_index) × 28 + final_index)
```

- 새 초성: 7
- 현대 한글 모음: 21
- 기존 한글 종성: 28 (종성 없음 포함)
- 총 7 × 21 × 28 = **4,116 음절**

새 종성 조합은 존재하지 않는다.

## 4. 저장 원칙

옛 자모 Unicode code point를 완성 문자열에 직접 저장하는 대신,
uHangul 완성 음절을 SPUA code point 하나로 저장한다.
옛 자모/θ는 glyph 디자인의 source shape로만 사용한다.

## 5. v0.4에서 제거된 기능

- 새 R 종성
- 새 F/V/Z/X/CH/TH 종성
- 새 초성 + 새 종성 조합
- 기존 초성 + 새 종성 조합

v0.5부터 확장 자음은 초성 전용이다.
