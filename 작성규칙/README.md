# 작성 규칙 안내

이 폴더는 Art Through Time의 재사용 가능한 화면·콘텐츠 작성 기준을 소유한다. 루트 [`README.md`](../README.md)는 프로젝트 목적, 현재 체계, 실행과 데이터 안내를 맡고, 이 폴더의 문서는 실제 수정 시 지켜야 할 탭별 규칙을 맡는다.

## 적용 순서

1. 저장소 전체 작업 규칙인 [`AGENTS.md`](../AGENTS.md)를 확인한다.
2. 모든 화면에 적용되는 [공통 탭 구조](공통_탭구조.md)를 적용한다.
3. 수정하는 화면의 탭별 작성 규칙을 적용한다.
4. `data/미술사조/*.html`을 건드리면 [사조 HTML 작성 규칙](사조html_작성규칙.md)을 추가 적용한다.
5. 데이터 파일의 스키마와 ID 불변식은 해당 JSON의 계약 및 검증 도구를 우선한다.

규칙이 충돌하면 더 구체적인 탭 문서를 따르되, 정본 JSON과 동기화 계약의 ID·데이터 소유권을 화면 규칙보다 우선한다.

## 문서 갱신 기준

- 다른 사조·화가·탭에도 다시 적용할 규칙, 예외, 레이아웃 표준, 검증 절차가 생기면 해당 작성규칙을 같은 작업에서 갱신한다.
- 한 화가명, 한 작품명, 한 설명 문장처럼 일회성인 데이터 교정은 작성규칙에 넣지 않는다.
- 수치가 정본 JSON에서 파생될 때는 무엇을 세는 숫자인지 함께 적고, 정본 구조가 바뀐 작업에서 문서의 수치도 갱신한다.
- 같은 규칙을 README와 여러 탭 문서에 길게 복제하지 않는다. 공통 규칙은 공통 문서에 두고 탭 문서는 예외와 추가 조건만 기록한다.
- 사조 HTML을 수정했지만 재사용 규칙이 바뀌지 않았다면 최종 작업 결과에 기존 규칙을 적용한 데이터·문구 변경임을 밝힌다.

## 공통 완료 조건

- 데이터의 실제 소유 파일과 화면의 파생 표시가 일치한다.
- 관리자와 보기 모드의 편집 권한이 섞이지 않는다.
- 외부 이미지 URL 의존이나 무승인 이미지 다운로드를 새로 만들지 않는다.
- `npm test`와 `git diff --check`를 통과한다.
- 사조 HTML 또는 제공 경로를 바꾼 경우 학습 길잡이 동기화 검사와 활성 문서 HTTP 검사를 추가한다.
- 검증 후 `node tools/record-change.js`로 날짜별 변경 기록을 남긴다.
