# 공통 탭 작성 규칙

새 탭·전용 화면은 이 문서를 먼저 적용하고, 탭별 문서는 여기서 더 필요한 규칙만 기록한다.

## 학습 설계 원칙

- 모든 탭은 미술사 초심자가 연대·국가·사조·화가·작품의 관계를 단계적으로 이해하도록 구성한다. 한 화면에서 모든 정보를 반복하지 않고 각 탭의 역할에 맞는 깊이만 제공한다.
- `미술 사조의 이해`는 학술적으로 엄밀한 전체 지도를, 사조 설명·국가별 미술·화가 리스트·화가 및 작품 탭은 초심자에게 선별된 이해 경로를 제공한다.
- 표시 이름을 화면별로 새로 만들지 않는다. 사조는 정본의 `parentId`·`categoryId`·`developmentId`, 화가와 작품은 `artistId`·`workId`를 사용해 연결한다.
- 설명은 단순한 유명도 나열보다 “무엇이 달라졌는가”, “작품의 어디를 보면 되는가”, “인접 개념과 어떻게 구분되는가”를 우선한다.

## 필수 구성

- 왼쪽 사이드바: 브랜드, 이름 표기 아이콘 `한 · u · 표`, 화면 제목, 탭 전용 제어, 로그아웃.
- 모든 왼쪽 사이드바의 우상단에는 아이콘 전용 보이기·감추기 토글을 둔다. 접힌 상태에서는 사이드바를 숨기고 본문이 남은 폭 전체를 사용하며, 화면 좌상단에 복원 토글만 남긴다. 접힘 상태는 브라우저 탭별로 독립 유지한다.
- 목록·필터가 없는 전용 탭도 이름 표기 아이콘과 로그아웃은 숨기지 않는다.
- 오른쪽 위: 탭 이동 버튼만 둔다. 전체 규칙 점검은 화면 버튼으로 노출하지 않으며, 필요할 때 개발·점검 절차에서 실행한다.
- 지도·연표·비교 화면: 사이드바를 제외한 오른쪽 주 화면의 가로 폭 전체를 사용한다. 불필요한 최대 폭·여백·기본 가로 스크롤을 만들지 않는다.
- 모든 탭에서 한국어(기본)·uHangul·국제 표기 상태를 동기화한다.
- 루트 진입의 기본 화면은 `미술 사조의 이해`이며, 화가 및 작품 탭은 `?artists=1`처럼 명시적인 탭 파라미터로 연다.
- `화가 및 작품`은 `?artists=1`, `화가 리스트`는 `?artistList=1`로 구분한다. 이름이 비슷해도 같은 탭 파라미터나 같은 `window.name`을 공유하지 않는다.
- 이름이 지정된 탭을 다시 열 때 대상 탭이 이미 존재해도 현재 URL이 요청 URL과 다르면 반드시 이동시켜 버튼과 화면 내용이 엇갈리지 않게 한다.

## 인증과 동기화

- 모든 탭은 `tab-session.js`와 uHangul 런타임을 포함한다. 규칙 점검용 클라이언트 스크립트는 탭 화면에 포함하지 않는다.
- 로그아웃은 서버 세션을 끝내고 `art-atlas-logout-signal`을 갱신한다.
- 새 프로젝트 탭은 같은 출처의 유효한 관리자 세션을 이어받아 편집 아이콘과 관리자 도구를 일관되게 표시한다. 세션 만료·로그아웃 시 공유 세션도 제거한다.
- 실행 파일이나 로그아웃에서 여는 `?login=1` 경로는 탭·공유 세션을 모두 지우고 로그인 화면을 먼저 표시한다.
- 신호를 받은 프로젝트 탭은 세션을 지우고 닫는다. 브라우저가 루트 탭 닫기를 막으면 로그인 화면으로 이동한다.
- 공용 `index.html` 기반의 새 탭은 URL별 화면 구성과 첫 데이터 렌더링이 완료되기 전 기본 화가 사이드바나 탭 이동을 노출하지 않는다. 로그인 대화상자는 이 초기 숨김의 영향을 받지 않아야 한다.

## 코드 분할과 규칙 점검

- 공용 앱은 고전 스크립트 순서인 `app-core.js`(공통 상태·데이터), `app-artists.js`(화가·작품), `app-atlas.js`(사조·국가), `app-detail.js`(상세 보기), `app.js`(초기화)를 유지한다. 앞 파일이 제공하는 전역 함수와 상태를 마지막 초기화 파일이 사용하므로 순서를 바꾸지 않는다.
- 서버는 `server.js`(인증·규칙 점검·라우팅), `server-data.js`(외부 조회·화가 저장·썸네일), `server-content.js`(사조 문서·업로드·정적 파일)로 나눈다. 새 공용 파일은 정적 파일 허용 목록에 함께 등록하고, 더 이상 참조하지 않는 화면용 파일을 제거할 때는 그 목록과 HTML의 참조도 같은 작업에서 제거한다.
- 코드 분할 뒤 규칙 점검이 화면 코드를 검사하는 경우에는 단일 진입 파일이 아니라 해당 기능의 실제 소유 모듈을 검사하고, 보고서의 파일명도 실제 모듈을 가리켜야 한다.

## 완료 전 확인

`한 · u · 표`, 로그아웃, 탭 이동, 오른쪽 주 화면 폭, 탭 간 로그아웃 동기화를 확인한다. `npm test`와 `git diff --check`를 실행하고, 수정한 화면은 실제 브라우저 폭에서 겹침·잘림·불필요한 가로 스크롤이 없는지 확인한다. 규칙 점검은 별도 개발 절차로 실행하며, 삭제한 전체 규칙 점검 UI의 버튼·CSS·클라이언트 스크립트를 다시 추가하지 않는다.

## 로컬 자산과 표시 일관성

- 모든 탭은 외부 이미지 URL이 아니라 프로젝트 로컬 이미지 경로를 사용한다. 다운로드용 로컬 파일을 화면 자산으로 등록할 때는 해당 탭의 데이터와 실제 파일 경로를 함께 확인한다.
- 기존 이미지 파일은 일괄 개명하지 않고 `data/image-catalog.json`에 `legacy`로 보존한다. 새 파일과 수정·교체하는 파일은 `간략이름_제목3단어_시작연도__workId.ext` 형식을 사용하며, 끝의 `workId`로 데이터 연결 안정성을 보존한다.
- 이미지 연결의 기준은 `artistId + workId`, 동일 파일 판정 기준은 SHA-256으로 한다. 이미지 변경 뒤 `node tools/build-image-catalog.js`를 실행하고, 다운로드 전에는 전역 카탈로그에서 작가명·작품명·QID·`workId`·해시를 검색한다.
- 외부 URL에서 이미지 파일을 내려받거나 URL 응답을 파일로 저장하려면, 실행 전에 대상 사이트·파일을 밝히고 사용자의 명시적 승인을 받는다. 로컬 파일이 이미 있으면 새 외부 다운로드보다 그 파일을 우선 사용한다.
- 새 데이터·카드·관계·기법을 추가한 뒤에는 현재 선택된 필터, 검색, 이름 표기 모드에서도 항목이 숨지 않는지 확인한다.
- URL 다운로드 스크립트를 추가하거나 수정하면 `tools/url-download-permission.js`의 `requireUrlFileDownloadApproval()`을 호출하고 `node tools/check-url-download-approval.js`를 통과해야 한다.
