# 새탭 template 작성 규칙

새 탭·전용 화면을 만들 때 기본적으로 갖추어야 할 구성을 정의한다. 새 탭 작업은 먼저 이 문서의 기본 구성, 인증·동기화, 코드 분할, 검증 기준을 구현한 뒤에 탭별 세부 기능과 화면 내용을 만든다.

모든 작업은 README의 `작업 전 필수 작성규칙` 절차에 따라 `AGENTS.md`, 이 새 탭 템플릿 규칙, 작업 대상 탭·문서의 세부 작성규칙을 먼저 확인한 뒤 진행한다. 기존 탭을 수정할 때도 공통 탭 구조나 인증·동기화·자산 규칙에 닿으면 이 문서를 함께 적용한다. 완료 보고에는 참고한 작성규칙과 실행한 검증을 남긴다.

## 학습 설계 원칙

- 모든 탭은 미술사 초심자가 연대·국가·사조·화가·작품의 관계를 단계적으로 이해하도록 구성한다. 한 화면에서 모든 정보를 반복하지 않고 각 탭의 역할에 맞는 깊이만 제공한다.
- `미술 사조의 이해`는 학술적으로 엄밀한 전체 지도를, 사조 설명·국가별 미술·화가 리스트·화가 및 작품 탭은 초심자에게 선별된 이해 경로를 제공한다.
- 표시 이름을 화면별로 새로 만들지 않는다. 사조는 정본의 `parentId`·`categoryId`·`developmentId`, 화가와 작품은 `artistId`·`workId`를 사용해 연결한다.
- 사조 국가 전개 행, 국가별 사조 막대, 화가 리스트 상자, 화가 연표 작품을 함께 바꾸는 작업은 `developmentId`와 `artistId + workId`를 기준으로 한 번에 갱신한다. 문자열 이름이 비슷하다는 이유로 연결을 추측하지 않으며 완료 전 `node tools/validate-cross-tab-linkage.js`로 전수 검사한다.
- 설명은 단순한 유명도 나열보다 “무엇이 달라졌는가”, “작품의 어디를 보면 되는가”, “인접 개념과 어떻게 구분되는가”를 우선한다.

## 관리자 예외 확인

- 관리자가 프로젝트 작성규칙의 분류 기준, 대표작 선정, 문구 기준, 파일명 선호, 화면 구성 기준과 다른 지시를 하면 즉시 거부하지 않는다. 먼저 어떤 작성규칙과 충돌하는지 짧게 밝히고, 이 작업에 한해 관리자 예외로 그대로 진행할지 확인한다.
- 관리자가 예외 진행을 명확히 확인하면, 확인된 지시를 우선해 구현한다. 완료 보고에는 어떤 작성규칙을 관리자 예외로 넘겼는지와 데이터·검증 결과를 함께 남긴다.
- 이 예외 절차는 이 저장소의 작성규칙 안에서만 적용한다. 시스템·개발자·보안·권한 규칙, 외부 URL 이미지 다운로드 사전 승인, 저작권·개인정보·파괴적 명령 승인처럼 상위 정책이나 실행 권한이 요구하는 절차는 관리자 예외로 생략하지 않는다.

## 필수 구성

- 왼쪽 사이드바: 브랜드, 이름 표기 아이콘 `한 · u · 표`, 화면 제목, 탭 전용 제어, 로그아웃.
- 모든 왼쪽 사이드바의 우상단에는 아이콘 전용 보이기·감추기 토글을 둔다. 접힌 상태에서는 사이드바를 숨기고 본문이 남은 폭 전체를 사용하며, 화면 좌상단에 복원 토글만 남긴다. 접힘 상태는 브라우저 탭별로 독립 유지한다.
- 목록·필터가 없는 전용 탭도 이름 표기 아이콘과 로그아웃은 숨기지 않는다.
- 오른쪽 위: 탭 이동 버튼만 둔다.
- 지도·연표·비교 화면: 사이드바를 제외한 오른쪽 주 화면의 가로 폭 전체를 사용한다. 불필요한 최대 폭·여백·기본 가로 스크롤을 만들지 않는다.
- 모든 탭에서 한국어(기본)·uHangul·국제 표기 상태를 동기화한다.
- 루트 진입의 기본 화면은 `미술 사조의 이해`이며, 화가 및 작품 탭은 `?artists=1`처럼 명시적인 탭 파라미터로 연다.
- `화가 및 작품`은 `?artists=1`, `화가 리스트`는 `?artistList=1`로 구분한다. 이름이 비슷해도 같은 탭 파라미터나 같은 `window.name`을 공유하지 않는다.
- 이름이 지정된 탭을 다시 열 때 대상 탭이 이미 존재해도 현재 URL이 요청 URL과 다르면 반드시 이동시켜 버튼과 화면 내용이 엇갈리지 않게 한다.

## 인증과 동기화

- 모든 탭은 `tab-session.js`와 uHangul 런타임을 포함한다.
- 로그아웃은 서버 세션을 끝내고 `art-atlas-logout-signal`을 갱신한다.
- 새 프로젝트 탭은 같은 출처의 유효한 관리자 세션을 이어받아 편집 아이콘과 관리자 도구를 일관되게 표시한다. 새 탭의 로그인은 이미 열린 탭의 유효한 관리자 세션을 무효화하지 않으며, 오래된 탭은 자신이 사용한 토큰과 일치할 때만 만료된 공유 세션을 제거한다. 명시적인 로그아웃은 모든 탭에 전파한다.
- 실행 파일이나 로그아웃에서 여는 `?login=1` 경로는 탭·공유 세션을 모두 지우고 로그인 화면을 먼저 표시한다.
- 신호를 받은 프로젝트 탭은 세션을 지우고 닫는다. 브라우저가 루트 탭 닫기를 막으면 로그인 화면으로 이동한다.
- 공용 `index.html` 기반의 새 탭은 URL별 화면 구성과 첫 데이터 렌더링이 완료되기 전 기본 화가 사이드바나 탭 이동을 노출하지 않는다. 로그인 대화상자는 이 초기 숨김의 영향을 받지 않아야 한다.

## 코드 분할과 검증

- 공용 앱은 고전 스크립트 순서인 `app/app-core.js`(공통 상태·데이터), `app/app-artists.js`(화가·작품), `app/app-atlas.js`(사조·국가), `app/app-detail.js`(상세 보기), `app/app.js`(초기화)를 유지한다. 앞 파일이 제공하는 전역 함수와 상태를 마지막 초기화 파일이 사용하므로 순서를 바꾸지 않는다.
- 이미 분리된 앱 스크립트와 이후 앱 기능 파일은 모두 루트 `app/` 폴더 아래에 둔다. 기능을 더 세분화할 때는 `app/core/`, `app/artists/`, `app/atlas/`, `app/detail/`처럼 `app/` 안의 기능별 하위 폴더를 사용하며, 루트에 새 `app-*.js` 파일이나 부모 파일별 폴더를 만들지 않는다. 새 고전 스크립트는 기존 의존 순서를 지키며 `index.html`에서 세부 파일을 먼저, 각 기능의 호환 진입점 파일을 나중에 로드한다.
- 서버는 `server.js`(인증·라우팅), `server-data.js`(외부 조회·화가 저장·썸네일), `server-content.js`(사조 문서·업로드·정적 파일)로 나눈다. 새 공용 파일은 정적 파일 허용 목록에 함께 등록하고, 더 이상 참조하지 않는 화면용 파일을 제거할 때는 그 목록과 HTML의 참조도 같은 작업에서 제거한다.
- 서버가 HTML을 동적으로 보강하는 공통 화면 규칙을 바꿀 때는 저장된 정본 HTML이나 생성·동기화 도구에도 같은 규칙을 남긴다. 서버 주입 CSS만 바꾸어 로컬 파일과 실제 응답의 기준이 갈라지게 하지 않는다.
- 기능을 삭제할 때는 화면 요소만 숨기지 말고 클라이언트 이벤트·CSS, 서버 API·보조 함수, 전용 데이터·일회성 도구를 함께 제거한다. 재등장하거나 남은 경로가 실제 요청을 처리할 위험이 있으면 `tools/check-project-health.js`와 HTTP 검사에 회귀 방지 항목을 추가한다.
- `+` 버튼으로 URL 자료 링크를 추가하는 화면은 URL 입력창 오른쪽과 확인 버튼 왼쪽에 `강조` 체크박스를 둔다. 강조한 링크는 URL과 함께 불리언 상태를 저장하고 원형 번호와 숫자를 기본 크기의 두 배로 표시하며, 링크 정렬·삭제 때도 강조 상태를 보존한다.

## 완료 전 확인

`한 · u · 표`, 로그아웃, 탭 이동, 오른쪽 주 화면 폭, 탭 간 로그아웃 동기화를 확인한다. `npm test`와 `git diff --check`를 실행하고, 실행 서버의 데이터 응답이나 사조 HTML 경로가 바뀐 작업은 서버 재시작 뒤 `node tools/check-app-http.js http://127.0.0.1:4173`으로 확인한다. 이 검사는 활성 사조 문서와 문서 안의 로컬 이미지도 전수 요청한다. 수정한 화면은 실제 브라우저 폭에서 겹침·잘림·불필요한 가로 스크롤이 없는지 확인한다.

## 로컬 자산과 표시 일관성

- 모든 탭은 외부 이미지 URL이 아니라 프로젝트 로컬 이미지 경로를 사용한다. 다운로드용 로컬 파일을 화면 자산으로 등록할 때는 해당 탭의 데이터와 실제 파일 경로를 함께 확인한다.
- 기존 이미지 파일은 일괄 개명하지 않고 `data/image-catalog.json`에 `legacy`로 보존한다. 새 파일과 수정·교체하는 파일은 `간략이름_제목3단어_시작연도__workId.ext` 형식을 사용하며, 끝의 `workId`로 데이터 연결 안정성을 보존한다.
- 이미지 연결의 기준은 `artistId + workId`, 동일 파일 판정 기준은 SHA-256으로 한다. 이미지 변경 뒤 `node tools/build-image-catalog.js`를 실행하고, 다운로드 전에는 전역 카탈로그에서 작가명·작품명·QID·`workId`·해시를 검색한다.
- 화가 작품은 `data/images/artist-*/`만 정본으로 사용한다. 다른 탭에서 같은 작품을 보여 줄 때도 이 파일을 재사용하며, 사조·기법·주제 전용 폴더에 같은 바이트의 복사본을 만들지 않는다. 다른 화면 전용 폴더에 더 나은 화가 작품 파일이 있으면 그 파일을 정본 폴더로 옮기고 모든 참조를 새 경로로 통일한다.
- 외부 URL에서 이미지 파일을 내려받거나 URL 응답을 파일로 저장하려면, 실행 전에 대상 사이트·파일을 밝히고 사용자의 명시적 승인을 받는다. 로컬 파일이 이미 있으면 새 외부 다운로드보다 그 파일을 우선 사용한다.
- 새 데이터·카드·관계·기법을 추가한 뒤에는 현재 선택된 필터, 검색, 이름 표기 모드에서도 항목이 숨지 않는지 확인한다.
- URL 다운로드 스크립트를 추가하거나 수정하면 `tools/url-download-permission.js`의 `requireUrlFileDownloadApproval()`을 호출하고 `node tools/check-url-download-approval.js`를 통과해야 한다.
