# 화가 관계도 탭 작성 규칙

화가 관계도 탭(`?artistRelations=1&artist=화가ID`)을 만들거나 수정할 때 [공통 탭 구조](공통_탭구조.md)와 함께 적용한다.

## 화면 구성

- 왼쪽 사이드바에는 브랜드, `한 · u · 표` 이름 표기 아이콘, `화가 관계도` 제목, 로그아웃을 유지한다.
- 사이드바 우상단의 아이콘 토글로 현재 브라우저 탭의 사이드바만 감추거나 보이게 한다. 접힘 상태는 다른 탭과 동기화하지 않는다.
- 오른쪽 위에는 공통 탭 이동 버튼만 둔다.
- 관계도 캔버스와 `영향을 준 event` 표는 사이드바를 제외한 오른쪽 주 화면의 가로 폭을 모두 사용한다.
- 데스크톱 관계도 캔버스의 기본 최소 높이는 448px로 유지한다. 화면 폭이 좁은 경우에는 관계군을 세로 흐름으로 전환해 필요한 높이를 확보한다.
- 중앙 대상 화가만 강조 타원으로 표시한다. 중앙 화가 외의 관계 인물은 관계 유형 박스 안에서 쉼표로 구분해 가로 나열한다.

## 관계 데이터와 링크

- 관계 데이터는 `data/artist-relations.json`의 화가 ID별 `study`, `teachers`, `exchanges`, `rivals` 배열에 저장한다.
- 화가의 개인사·환경 변화가 작품 활동에 직접적인 영향을 준 경우, 같은 화가 데이터의 `impactEvents` 배열에 `year`, 다국어 `title`·`impact`, 검증 가능한 `source`를 저장하고 관계도 아래 표로 표시한다. `source`는 검증용 데이터이며 화면에는 노출하지 않는다.
- 화가를 이해하는 기초 배경이 중요한 경우 `impactEvents`의 첫 항목에 출생 연월·국가와 지역·부모·성장 환경을 사실에 근거해 서술한다.
- `영향을 준 event` 표의 사건명은 왼쪽 정렬하며, 제목·행 여백·행간은 한 화면에 가능한 많은 사건을 읽기 좋게 표시하는 밀도로 유지한다.
- 관계는 확인 가능한 출처가 있을 때만 등록한다. 스승·경쟁·영향 관계를 추정으로 채우지 않는다.
- `study`, `teachers`, `exchanges`, `rivals`에는 미술가·제작자처럼 관계도에 표시할 인물만 넣는다. 군주, 후원자, 수집가, 정치인, 가족 등 비미술 인물은 관계 타원에 넣지 않고, 작품 활동에 미친 영향이 확인된 경우에만 `impactEvents`에 기록한다.
- 협업자는 공동 제작·화실·동일 프로젝트의 역할이 확인된 경우에만 `exchanges`에 넣는다. 영향 관계와 실제 교류·경쟁 관계를 서로 대체하지 않는다.
- 화가 목록에 등록된 인물은 목록과 같은 짧은 통용명, 내부 연표 링크, 금색 타원으로 표시한다.
- 목록에 없는 외부 인물은 `wikipedia` 링크를 사용한다. 출처 링크가 없으면 `agentAnswer` 안내만 표시한다.
- 여러 인물은 쉼표로 구분하며, 이름 표기 모드가 내부 화가 링크와 중앙 화가에 적용되어야 한다.

## 영향 사건 표

- 관계도 데이터의 `impactEvents`가 있는 화가만 관계도 바로 아래에 `영향을 준 event` 표를 표시한다. 표는 관계도와 마찬가지로 사이드바를 제외한 오른쪽 주 화면 전체 폭을 사용한다.
- 각 항목은 `year`, 다국어 `title`, 다국어 `impact`, 검증용 `source`를 갖는다. `source`는 데이터 검증용으로만 보관하며 화면에는 표시하거나 링크하지 않는다.
- 첫 항목에는 화가 이해에 필요한 출생 연월, 국가·지역, 부모 또는 가족 배경, 성장 환경을 사실에 근거해 요약한다. 이후 항목은 작품 활동의 방향·주제·매체·인적 관계를 바꾼 개인사 또는 환경 변화만 수록한다.
- 화가가 생존 중 직접 겪었고 작품·이동·후원·표현에 영향을 준 전쟁, 침략, 점령, 혁명, 내전, 포위, 강제 이주 사건은 별도 `impactEvents` 항목으로 반드시 확인해 수록한다. 단, 단순히 동시대에 일어난 전쟁이나 영향이 확인되지 않는 사건은 넣지 않는다.
- 질병·시력 상실·가족사·교육·궁정·제도·시장·해외 체류도 작업 매체, 수주, 이동, 표현에 직접 영향을 준 근거가 있을 때만 사건으로 기록한다. 가능성 또는 미술관의 신중한 해석은 단정하지 말고 그 한계를 `impact`에 명시한다.
- 화가 연표에 새 썸네일 또는 고해상도 이미지를 추가하면 서버는 `tools/artist-relation-impact-audit.js`를 자동 실행해 `data/artist-relation-impact-audits.json`에 점검 결과를 남긴다. 이 점검은 관계도 데이터 존재, 사건 수, 첫 배경 사건, 한·영 제목·영향 설명·출처 URL, 역사 직접영향 후보 수를 검사한다.
- 자동 점검 결과의 `historicalReview.status`가 `pending-source-review`이면, 새 이미지와 관련해 해당 화가가 직접 겪은 전쟁·침략·점령·혁명·내전·포위·강제 이주·역병을 검증 출처로 다시 확인한다. 직접 영향이 입증된 경우에만 `impactEvents`에 추가하고, 단순 동시대 사건은 추가하지 않는다.
- 표의 열은 `연도 / 사건 / 영향` 순서로 두며, 사건명은 왼쪽 정렬한다. 제목 글자는 기본 관계도 제목보다 작게(약 80%) 표시한다.
- 한 화면에 가능한 많은 사건을 읽기 좋게 표시하도록 표 머리글·행의 세로 여백과 본문 행간을 작게 유지한다. 작은 화면에서는 가로 스크롤 없이 2열 흐름으로 재배치한다.
- 연도는 단일 연도 또는 필요한 범위(`1878–1879`)로 기록한다. 단순한 추정·소문·작품과 무관한 일화는 넣지 않는다.

## 관계 박스와 연결선

- 관계 유형은 독립 박스로 묶어 관계군을 명확히 구분한다. 교류는 옅은 하늘색, 대립·경쟁은 옅은 적색 계열을 쓴다.
- 연결선은 중앙 화가에서 각 관계 박스의 중심 쪽 모서리로 이어진다. 위쪽 박스는 아래 모서리, 아래쪽 박스는 위 모서리에서 선이 닿게 한다.
- 관계군의 첫 이름은 중앙에 가까운 박스 안쪽 가장자리에서 시작한다. 불필요한 가로 스크롤이나 세로 나열을 만들지 않는다.

## 완료 전 검증

- `한 · u · 표`, 로그아웃, 탭 이동 버튼, 오른쪽 주 화면 폭이 유지되는지 확인한다.
- 등록 화가·위키피디아 인물·AI 안내 인물의 링크 동작을 각각 확인한다.
- `node --check app.js`와 `node tools/check-project-health.js`를 실행한다.
- 이미지 추가 자동 점검은 `node tools/artist-relation-impact-audit.js --artist <artistId> --work <workId>`로 수동 재실행할 수 있으며, `data/artist-relation-impact-audits.json`의 해당 결과를 확인한다.
