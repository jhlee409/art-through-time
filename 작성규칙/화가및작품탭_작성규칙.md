# 화가 및 작품 탭 작성 규칙

[공통 탭 구조](공통_탭구조.md)를 함께 적용한다.

- 화가와 작품의 원본은 `data/artists.json`이며, `data/artists-index.json`은 화면 로딩용 파생 색인이다. 색인을 직접 원본처럼 편집하지 않는다.

- 한국어 목록명은 정식 전체 이름이 아니라 실제 통용 짧은 이름을 기본으로 한다.
- 사이드바 우상단의 아이콘 토글로 현재 브라우저 탭의 사이드바만 감추거나 보이게 한다. 접힘 상태는 다른 탭과 동기화하지 않는다.
- 오른쪽 작품 화면은 사이드바를 제외한 본문 가로 공간을 전부 사용한다. 큰 좌우 여백이나 고정 폭 작품 그리드 때문에 오른쪽에 빈 공간이 남지 않게 한다.
- 작품 연표 제목의 화가 이름은 현재 화가의 이름 텍스트로 표시한다.
- 작품 연표가 처음 열리거나 외부 링크로 특정 화가가 열릴 때는 왼쪽 화가 목록의 선택 행을 목록 스크롤 영역 세로 중앙에 표시한다. 사용자가 왼쪽 목록에서 직접 화가를 선택할 때는 선택 전 목록 스크롤 위치를 유지해 현재 보던 화가 목록 위치가 움직이지 않게 한다. 이 동작은 오른쪽 연표의 스크롤 위치를 변경하지 않는다.
- 시기별 연표의 시간 구분은 `18세기`처럼 세기 단위로 간략 표기한다. 세기 제목은 해당 세기 영역 가운데 정렬하고, 각 세기 섹션 경계에는 수평선을 두며, 세기 박스는 하나 건너 옅은 복숭아색 배경을 넣는다.
- 일반 작품 세로 연표를 사용할 때도 왼쪽 축은 개별 제작 연도 대신 `18세기` 같은 세기 박스로 표시하고, 정확한 제작 연도는 작품 행 안의 작은 보조 표기로 남긴다.
- 작품 이미지·고해상도 파일은 로컬 경로를 사용하며 수동 추가 작품의 `origin: "manual"`을 보존한다.
- 작품 이미지는 `data/images/artist-*/`에 두고 고해상도 전용 `data/high-resolution/` 폴더는 새로 쓰지 않는다. 기존 파일은 일괄 개명하지 않고 `data/image-catalog.json`의 `legacy` 항목으로 보존한다. 새 파일과 수정·교체하는 파일의 표준명은 `간략이름_제목3단어_시작연도__workId.ext`로 한다. `간략이름`은 화가 목록의 짧은 한국어 이름을 우선하고, `제목3단어`는 표준 한국어 작품 제목의 앞 3단어를 사용하며, `시작연도`는 `year` 또는 `yearLabel`의 첫 연도를 사용한다. 제목·연도가 불확실하면 파일을 임의 이름으로 등록하지 않고 대기 상태를 유지한다.
- 작품과 이미지의 정본 연결 키는 `artistId + workId`이며, 동일 파일은 SHA-256으로 판정한다. 이미지 추가·교체·삭제 뒤 `node tools/build-image-catalog.js`로 전역 색인을 갱신하고 `node tools/build-image-catalog.js --check`를 통과시킨다.
- 사조 설명에서 같은 작품을 사용할 때도 `data/images/artist-*/`의 정본 파일을 참조한다. 화가 연표 작품을 `data/미술사조/images/`에 별도 복사하거나 두 폴더의 파일을 서로 다른 작품처럼 등록하지 않는다.
- 외부 다운로드 후보를 만들기 전에 `node tools/find-artwork-image.js` 또는 동일한 카탈로그 조회 함수를 사용해 작가명·작품명·작품 QID·`workId`·SHA-256 순으로 로컬 파일을 확인한다. 일치 파일이 있으면 새 다운로드보다 기존 연결 복구를 우선한다.
- 사용자가 `다운로드용/`에 넣은 작품 파일은 요청 범위 안에서 모두 점검해 작품 연표에 등록한다. 같은 작품의 새 파일이면 중복 작품을 만들기보다 기존 작품의 로컬 썸네일·고해상도 연결을 교체한다.
- 로컬 파일을 등록할 때는 화가별 `data/images/artist-*/`에 복사하고, 작품마다 숫자 `year`(필요하면 `yearEnd`), 한·영 제목·설명, 매체, 활동 당시 국가·지역, 로컬 출처 문구, 이미지 상태를 함께 기록한다. 제목·연도가 확정되지 않으면 추정값을 확정 사실처럼 쓰지 않는다.
- 대표작 또는 사조 카드의 기준 작품이 바뀌면 `featuredWorkIds`, `data/art-movement-representatives.json`의 `workId`·선정 이유, 사조 설명 카드의 이미지·제목·연도·설명을 같은 작업에서 함께 맞춘다. 사조 카드의 작품은 유명도만으로 고르지 않고 해당 범주의 핵심 특징과 화가 선정 이유를 가장 직접적으로 설명해야 한다.
- 사조 설명 표의 대표 화가와 더 볼 화가로 연결된 인물은 같은 `developmentId`의 작품 카드에도 있어야 한다. 표에 없는 화가를 카드 수를 채우기 위해 추가하지 않는다.
- 더 볼 화가를 새로 연결할 때는 `data/artists.json`에 생몰년·활동 국가·사조·세부 사조와 해당 사조를 설명하는 대표작 1개를 함께 등록한다. 승인된 공개 도판이 있으면 로컬 파일·원본 페이지·라이선스를 보존하고, 도판을 확보하지 못했더라도 화가와 텍스트 연결은 유지한 채 작품 이미지를 `다운로드 필요` 상태로 둔다.
- 화가 연표에서는 `movementContributionReason`이 `canonical-movement-representative`인 대표 화가의 기준 작품 이미지에만 3px 굵기의 붉은 실선 테두리를 표시한다. 더 볼 화가의 작품과 그 밖의 작품에는 별도 강조 테두리·외곽선·그림자·제목색을 적용하지 않는다.
- Firebase 내보내기는 향후 이관 준비 기능이며 로컬 JSON을 원본으로 유지한다.
- `data/artists.json`을 수정한 작업에서는 `node tools/build-artist-index.js`로 파생 색인을 갱신한다. 이후 `node tools/validate-project-linkage.js --image-indexes`, `node tools/validate-cross-tab-linkage.js`, `node tools/validate-movement-representatives.js`, `node tools/validate-movement-links.js`, `npm test`, `git diff --check`를 실행한다. 이미지 파일을 바꿨다면 `node tools/build-image-catalog.js --check --hashes`도 실행한다. 보조 색인에 삭제된 작품이나 무효 경로가 남으면 `node tools/sync-image-indexes.js --write`로 현재 작품 데이터에 맞춘다.
