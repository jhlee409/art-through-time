# 화가 및 작품 탭 작성 규칙

[공통 탭·전용 HTML 작성 규칙](새탭_template_작성규칙.md)을 함께 적용한다. 이 탭이나 화가·작품 원본, 작품 연표, 이미지 동작을 수정하기 전에는 README의 `작업 전 필수 작성규칙` 절차와 이 문서를 먼저 확인한다.

화가 해설의 자료 입력, 병합, 모순 확인, 접기·펼치기와 작품명 연결은 [화가 설명 작성 규칙](화가설명_작성규칙.md)을 따른다.

- 화가와 작품의 원본은 `data/artists.json`이며, `data/artists-index.json`은 화면 로딩용 파생 색인이다. 색인을 직접 원본처럼 편집하지 않는다.

- 한국어 목록명은 정식 전체 이름이 아니라 실제 통용 짧은 이름을 기본으로 한다.
- 화가 및 작품 탭의 왼쪽 화가 목록 정렬 기본값은 글자 오름차순(`nameAsc`)으로 둔다. 사용자가 선택하기 전 초기 화면에서 생년순이 기본이 되지 않게 한다.
- 화가 선택은 선택 위치만 브라우저에 저장하며 화가 원본 저장을 예약하지 않는다. 화가 링크, 작품 링크, 대표작 선택·순서는 원본 작품 목록을 건드리지 않는 `/api/artist-presentation` 부분 저장을 사용한다.
- 화가·작품의 자료 URL 입력창과 확인 버튼 사이에 `강조` 체크박스를 둔다. 체크해 추가한 링크는 `{url, emphasized:true}`로 저장하며, 화가 제목·작품 상세의 24px 원형 번호는 48px로, 작품 카드의 19px 번호는 38px로 확대하고 숫자 크기도 각각 두 배로 표시한다.
- 오른쪽 작품 이미지를 더블클릭하면 원본 비율을 유지하면서 긴 변이 화면의 90%에 닿는 확대 박스를 연다. 이미지는 박스를 채우고 좌측 하단에 화가의 짧은 이름·작품명·연도를 표시한다. 확대 이미지 위에서는 커서 위치를 중심으로 3배 확대된 부분을 전체 이미지 높이의 2/3 지름인 원형 돋보기에 표시하고, 이미지를 더블클릭하면 확대 박스를 닫는다.
- 화가 설명 문장 안에 자동 연결된 작품명을 클릭해 여는 이미지 미리보기 박스는 원본 비율을 유지하면서 화면 가로·세로의 최대 80% 안에 맞춘다. 이미지를 더블클릭하거나 Esc를 누르면 닫힌다.
- 작품 확대 박스와 원형 돋보기는 특정 화가가 아니라 화가 및 작품 탭의 모든 화가 연표에 동일하게 적용한다. `timeline` 화면과 `.artist-timeline-panel` 안에서만 이벤트를 연결하며, 국가별 미술·화가 리스트·사조·기법·용어·주제 탭의 이미지 동작에는 이 규칙을 적용하지 않는다.
- 오른쪽 작품 화면은 사이드바를 제외한 본문 가로 공간을 전부 사용한다. 큰 좌우 여백이나 고정 폭 작품 그리드 때문에 오른쪽에 빈 공간이 남지 않게 한다.
- 오른쪽 작품 카드에는 작품명과 함께 제작 연도, 번역된 작품 설명을 항상 표시한다. 소장처가 있으면 연도와 같은 보조 정보 행에 함께 표시하고, 연도가 없으면 `연도 미상`을 표시한다. 설명은 카드 높이가 지나치게 늘어나지 않도록 최대 4줄까지 보이게 하되 전체 문장은 `title` 툴팁으로 확인할 수 있어야 하며, 연표 축에 연도가 표시되어도 카드의 연도 표기를 생략하지 않는다.
- 작품 연표 제목의 화가 이름은 현재 화가의 이름 텍스트로 표시한다.
- 작품 연표가 처음 열리거나 외부 링크로 특정 화가가 열릴 때는 왼쪽 화가 목록의 선택 행을 목록 스크롤 영역 세로 중앙에 표시한다. 사용자가 왼쪽 목록에서 직접 화가를 선택할 때는 선택 전 목록 스크롤 위치를 유지해 현재 보던 화가 목록 위치가 움직이지 않게 한다. 이 동작은 오른쪽 연표의 스크롤 위치를 변경하지 않는다.
- 시기별 연표의 시간 구분은 제작 시작 연도 기준 `1890년대`처럼 10년 단위로 간략 표기한다. 10년대 제목은 해당 구간 영역 가운데 정렬하고, 각 구간 섹션 경계에는 수평선을 두며, 구간 박스는 하나 건너 옅은 복숭아색 배경을 넣는다.
- 작품 보기 방식에는 `전체 작품`, `10년 연표`, `초상화·연작`을 둔다. 처음 여는 화가의 기본 보기는 `10년 연표`이며, 사용자가 같은 화가에서 선택해 저장한 보기 방식은 유지한다. `초상화·연작` 보기에서 초상화는 현재 화가의 표시 가능한 작품 중 두 점 이상일 때만 한 줄로 보이고, 한 점뿐이면 숨긴다. 연작은 같은 작품명이 두 점 이상에서 반복되거나 한 작품명이 다른 작품명 안에 포함되는 경우에만 같은 이름의 연작 줄로 묶어 보이며, 한 번만 등장한 작품명은 연작 줄에 표시하지 않는다. 같은 작품의 한국어·영어·원어 제목과 `A and B`/`A와 B`처럼 대응되는 제목 조각은 같은 의미의 별칭으로 한 번 더 병합해 `수련 = Water Lilies`, `일본식 다리 = Japanese Bridge`처럼 언어 차이로 연작 줄이 갈라지지 않게 한다. `Portrait of ...`처럼 장르 일반어만 반복되는 경우는 연작으로 묶지 않고 초상화 줄에서만 다룬다.
- 일반 작품 세로 연표를 사용할 때도 왼쪽 축은 개별 제작 연도 대신 `18세기` 같은 세기 박스로 표시하고, 정확한 제작 연도는 작품 행 안의 작은 보조 표기로 남긴다.
- 작품 이미지·고해상도 파일은 로컬 경로를 사용하며 수동 추가 작품의 `origin: "manual"`을 보존한다.
- 같은 화가 연표 안에서 한글·영어·원어 제목을 비교해 같은 작품으로 판단되는 중복 작품은 한 항목만 남긴다. 보존 우선순위는 이미지 픽셀 면적이 큰 항목, 같은 크기이면 한국어 제목이 제대로 들어간 항목, 그다음 로컬 이미지 항목이다. 단순히 같은 제목을 공유하는 연작·같은 주제의 다른 작품은 중복으로 삭제하지 않는다.
- 자동 수집 작품의 60개 선택 상한은 아직 로컬 이미지가 없는 후보에만 적용한다. `data/images/` 아래 로컬 이미지가 연결된 작품은 이미 확보한 정본 자료이므로 상한을 넘더라도 `data/artists.json`, 화면 로딩, 자동 통합 과정에서 삭제하거나 제외하지 않는다.
- 작품 이미지는 `data/images/artist-*/`에 두고 고해상도 전용 `data/high-resolution/` 폴더는 새로 쓰지 않는다. 이 프로젝트에서 `data/images`는 `C:\Users\admin\OneDrive - UOU\AI-Programming\Art_through_Time\data\images`를 가리키는 Windows Junction이며, 실제 대량 이미지 정본은 OneDrive에 있다. 따라서 이미지는 Junction 경로를 통해 추가·교체하고, Junction을 일반 폴더로 바꾸거나 대량 이미지를 Git에 넣지 않는다. 기존 파일은 일괄 개명하지 않고 `data/image-catalog.json`의 `legacy` 항목으로 보존한다. 새 파일과 수정·교체하는 파일의 표준명은 `간략이름_제목3단어_시작연도__workId.ext`로 한다. `간략이름`은 화가 목록의 짧은 한국어 이름을 우선하고, `제목3단어`는 표준 한국어 작품 제목의 앞 3단어를 사용하며, `시작연도`는 `year` 또는 `yearLabel`의 첫 연도를 사용한다. 제목·연도가 불확실하면 파일을 임의 이름으로 등록하지 않고 대기 상태를 유지한다.
- 작품과 이미지의 정본 연결 키는 `artistId + workId`이며, 동일 파일은 SHA-256으로 판정한다. 이미지 추가·교체·삭제 뒤 `node tools/build-image-catalog.js`로 전역 색인을 갱신하고 `node tools/build-image-catalog.js --check`를 통과시킨다. OneDrive 온라인 전용 파일처럼 경로는 존재하지만 일시적으로 읽을 수 없는 기존 파일은 직전 카탈로그의 크기·해시를 보존하고 `inaccessible` 목록으로 보고하며, 새 파일은 실제 해시를 읽기 전까지 등록하지 않는다.
- 사조 설명에서 같은 작품을 사용할 때도 `data/images/artist-*/`의 정본 파일을 참조한다. 화가 연표 작품을 `data/미술사조/images/`에 별도 복사하거나 두 폴더의 파일을 서로 다른 작품처럼 등록하지 않는다. 다른 화면 전용 폴더의 파일이 더 선명하거나 여백이 적어 정본으로 삼기에 적합하면, 그 파일을 화가별 정본 폴더의 표준명으로 옮긴 뒤 기존 작품의 이미지 경로를 교체한다.
- 외부 다운로드 후보를 만들기 전에 `node tools/find-artwork-image.js` 또는 동일한 카탈로그 조회 함수를 사용해 작가명·작품명·작품 QID·`workId`·SHA-256 순으로 로컬 파일을 확인한다. 일치 파일이 있으면 새 다운로드보다 기존 연결 복구를 우선한다.
- 사용자가 `다운로드용/`에 넣은 작품 파일은 요청 범위 안에서 모두 점검해 작품 연표에 등록한다. 같은 작품의 새 파일이면 중복 작품을 만들기보다 기존 작품의 로컬 썸네일·고해상도 연결을 교체한다.
- 로컬 파일을 등록할 때는 화가별 `data/images/artist-*/`에 복사하고, 작품마다 숫자 `year`(필요하면 `yearEnd`), 한·영 제목·설명, 매체, 활동 당시 국가·지역, 로컬 출처 문구, 이미지 상태를 함께 기록한다. 제목·연도가 확정되지 않으면 추정값을 확정 사실처럼 쓰지 않는다.
- 2026-09-03부터 새로 수동 등록하는 로컬 작품 이미지(`origin: "manual"`)는 먼저 `imageOwnershipVerification.status: "pending"`으로 기록한다. 정기 점검 때 `npm run images:ownership-audit`를 실행해 작품 QID의 Wikidata P170(창작자)을 화가 QID와 대조하고, 일치하면 같은 필드를 `verified` 상태와 대조 시각으로 갱신한다. QID가 없어 자동 대조할 수 없는 항목은 대표작·즐겨찾기·사조 기준 작품으로 지정하지 않고 보류한다. 점검 후 미확인·불일치 항목까지 오류로 확인하려면 `npm run images:ownership-check`를 실행한다.
- 대표작 또는 사조 카드의 기준 작품이 바뀌면 `featuredWorkIds`, `data/art-movement-representatives.json`의 `workId`·선정 이유, 사조 설명 카드의 이미지·제목·연도·설명을 같은 작업에서 함께 맞춘다. 사조 카드의 작품은 유명도만으로 고르지 않고 해당 범주의 핵심 특징과 화가 선정 이유를 가장 직접적으로 설명해야 한다.
- 사조 설명 표의 대표 화가와 더 볼 화가로 연결된 인물은 같은 `developmentId`의 작품 카드에도 있어야 한다. 표에 없는 화가를 카드 수를 채우기 위해 추가하지 않는다.
- 더 볼 화가를 새로 연결할 때는 `data/artists.json`에 생몰년·활동 국가·사조·세부 사조와 해당 사조를 설명하는 대표작 1개를 함께 등록한다. 승인된 공개 도판이 있으면 로컬 파일·원본 페이지·라이선스를 보존하고, 도판을 확보하지 못했더라도 화가와 텍스트 연결은 유지한 채 작품 이미지를 `다운로드 필요` 상태로 둔다.
- 화가 연표에서는 `movementContributionReason`이 `canonical-movement-representative`인 대표 화가의 기준 작품 이미지에만 3px 굵기의 붉은 실선 테두리를 표시한다. 더 볼 화가의 작품과 그 밖의 작품에는 별도 강조 테두리·외곽선·그림자·제목색을 적용하지 않는다.
- Firebase 내보내기는 향후 이관 준비 기능이며 로컬 JSON을 원본으로 유지한다.
- `data/artists.json`을 수정한 작업에서는 `node tools/build-artist-index.js`로 파생 색인을 갱신한다. 공통 규칙의 기본 검사에 추가해 `node tools/validate-artist-ownership.js`, `node tools/validate-project-linkage.js --image-indexes`, `node tools/validate-cross-tab-linkage.js`, `node tools/validate-movement-representatives.js`, `node tools/validate-movement-links.js`를 실행한다. `validate-artist-ownership.js`는 생성 원본의 QID·화가 ID가 현재 화가 레코드와 같은 소유자인지 검사한다. 생성 원본 스냅샷 밖의 `generated` 작품은 Wikidata의 제작자(P170) 대조 결과를 `ownershipVerification`에 기록하지 않으면 실패해야 한다. 이미지 파일을 바꿨다면 `node tools/build-image-catalog.js --check --hashes` 또는 `npm run test:deep`도 실행한다. 보조 색인에 삭제된 작품이나 무효 경로가 남으면 `node tools/sync-image-indexes.js --write`로 현재 작품 데이터에 맞춘다.
