# 화가 설명 작성 규칙

[공통 탭·전용 HTML 작성 규칙](새탭_template_작성규칙.md)과 [화가 및 작품 탭 작성 규칙](화가및작품탭_작성규칙.md)을 함께 적용한다. 이 문서는 `화가 및 작품` 탭의 화가 해설 작성·md 업로드·스크립트 요약·문서형 변환·표시 기능에 대한 세부 정본이다. 화가 해설 자료·병합·작품명 연결을 수정하기 전에는 README의 `작업 전 필수 작성규칙` 절차와 이 문서를 먼저 확인한다.

## 적용 범위와 데이터 소유권

- 화가 설명 기능은 특정 화가의 예외 기능이 아니다. `data/artists.json`에 등록된 모든 화가의 공통 연표 화면에 같은 데이터 구조, 버튼, 병합 규칙, 접기·펼치기 및 작품 연결 동작을 적용한다.
- 화가를 바꾸어도 `app/app-artists.js`의 공통 `renderTimeline()`과 선택된 `artist` 객체를 사용한다. 화가 ID나 이름을 검사하는 개별 분기를 만들지 않는다.
- 해설 원문은 화가의 `artistSummary.ko`·`artistSummary.en` 배열에 저장한다. 스크립트 원문은 기본 저장 대상이 아니며, `스크립트 요약` 결과만 해설 배열에 저장한다.
- 직접 편집한 해설은 전체 `artists` 컬렉션 저장이 아니라 화가별 부분 저장 API로 갱신한다. 서버는 `artistSummaryUpdatedAt`을 기록하고, 화면이 읽어 온 기준 시각과 다르면 충돌로 거부해 오래 열린 탭의 저장이 최신 해설을 덮어쓰지 못하게 한다. 충돌 시 화면의 입력 내용은 저장하지 않고 최신 내용을 다시 확인하도록 안내한다.
- 화가 링크는 `links[]`에 저장하며 URL과 강조 여부를 보존한다. 이전 데이터와 호환하기 위해 유튜브 링크의 기존 스크립트 필드는 보존할 수 있지만, 새 해설 흐름에서는 `스크립트 요약` 결과를 `artistSummary.ko`에 저장한다.
- 화가 원본을 저장하면 `data/artists-index.json`도 다시 생성한다. 파생 색인을 직접 수정하지 않는다.

## 자료 입력과 변환

- `편집`은 일반 텍스트, 블로그 본문, 직접 조사한 문장을 외부 웹 읽기 없이 직접 입력·수정·저장하는 기능이다.
- `md 업로드`는 `편집` 오른쪽에 두며, 로컬 `.md` 또는 `.markdown` 파일을 브라우저에서 읽어 편집창의 기존 내용 뒤에 `## md 업로드: 파일명` 블록으로 추가한다. md 업로드 자체는 서버 업로드나 OpenAI 요청을 실행하지 않는다.
- `스크립트 요약`은 `md 업로드` 오른쪽에 두며, 긴 스크립트를 입력받아 OpenAI API로 요약한 뒤 원문이 아니라 요약 결과만 `## 스크립트 요약: 제목` 블록으로 해설에 저장한다. 스크립트 요약 입력은 120,000자까지 허용한다.
- `변환`은 현재 저장된 일반 텍스트·블로그 본문·md 업로드 블록·스크립트 요약 블록만 OpenAI API로 전송해 문서형 해설로 다듬고 바로 저장한다. 블로그 URL, 외부 웹페이지, 링크에 남아 있는 긴 스크립트를 서버가 별도로 읽거나 자동 반영하지 않는다.
- 영상·음원·이미지 파일을 자동 다운로드하지 않는다. 이미지 다운로드가 필요한 별도 작업에는 저장소의 이미지 파일 다운로드 승인 규칙을 적용한다.

## 작성 내용

- 해설은 화가의 생애와 화풍을 이해하는 데 직접 필요한 사건과 맥락을 문서형 해설로 작성한다.
- 출생 환경이 화풍에 준 영향, 초기 미술 습득 관계, 스승과 사제 관계 및 스승의 작품 경향, 모사·연구한 이전 대가, 우호적 교류, 반목·경쟁, 작업에 영향을 준 전쟁·사고·질병·전염병, 거주 국가·지역 이동을 다룬다.
- 화풍과 사조의 변화는 자료에서 언급한 작품을 프로젝트 작품 목록과 대조한 뒤 `《작품명》(제작연도)` 형식으로 설명한다. 프로젝트에 없는 작품·연도나 자료에 없는 인과관계를 만들어 내지 않는다.
- 전쟁을 피한 이동처럼 자료가 밝힌 원인을 생략하지 않는다. 뒤에 같은 사조의 핵심 집단을 이룬 긴밀한 동료가 자료에 나오면 그 화가들의 이름을 적는다.
- 변환은 저장된 해설 입력 기록에서 확인되는 내용만 사용한다. 단순 출생·사망 기록, 정보가 없다는 문장, 자료가 제한적이라는 안내 문구는 생성하지 않는다.
- 변환은 사용자가 입력한 기존 해설의 순서, md 업로드로 추가한 순서, 스크립트 요약으로 저장한 순서를 유지한다. 서로 다른 입력 블록의 내용을 하나로 통합하거나 연도순으로 재배치하지 않는다.
- 화면 해설에는 출처명과 `연도 미상` 문구를 붙이지 않는다. 기존의 날짜 불명 항목은 삭제하지 않고 `[확인 필요]`로 바꾸어 정렬 마지막에 둔다.
- 이미지 URL이나 이미지 마크다운은 최종 해설에 URL 또는 이미지로 남기지 않는다. 작품명과 연도를 확인할 수 있으면 텍스트로만 남기고, 확인할 수 없으면 생략한다.

## 순서 보존과 정리

- 변환 전의 기존 해설은 기본적으로 모두 보존한다. 스크립트 요약 블록이나 md 업로드 블록이 기존 내용을 언급하지 않았다는 이유로 기존 항목을 삭제하지 않는다.
- 의미가 같더라도 서로 다른 입력 블록에 있는 내용은 한 항목으로 합치지 않는다.
- 날짜와 나이가 확인된 항목도 전체 해설을 연도순으로 재정렬하지 않는다. 필요한 경우 각 입력 블록 안에서만 소제목, 강조, 표를 적용해 읽기 쉽게 다듬는다.
- 나이는 화가의 출생 연도와 사건 연도의 차이로 계산해 `연도 (약 나이세)` 형식으로 표시한다.
- 기존 문장을 사용자가 직접 편집한 경우에도 다음 변환에서 삭제 대상으로 간주하지 않는다.

## 모순 확인

- 새 자료와 기존 해설이 동시에 참일 수 없는 경우에만 모순으로 분류한다. 단순한 정보 추가, 상세 정도 또는 표현의 차이는 모순이 아니다.
- 모순이 발견되면 자동으로 기존 문장을 교체하지 않고 `[확인 필요]` 문장으로 남긴다.
- 스크립트 요약과 변환 결과는 저장 전 입력 기록을 자동 삭제하지 않는다. 모순이 있으면 같은 입력 블록 안에 `[확인 필요]`로 남긴다.

## 화면 표시와 조작

- 화가 해설 상자는 해설 유무와 관계없이 모든 화가 연표의 작품 목록 위에 표시한다.
- 직접 편집하거나 자동 병합한 해설 원문은 텍스트 배열로 저장하고, 읽기 화면에서만 제한된 문서형 HTML로 렌더링한다. `#` 제목, `>` 인용, `**굵게**`, 안전한 텍스트 링크, 마크다운 표는 시각 요소로 바꾸되 원본 HTML 태그는 실행하지 않고 텍스트로 이스케이프한다. 외부 이미지 마크다운은 새 이미지 URL 의존을 만들지 않고 `이미지 업로드 예정` 상태로 표시한다.
- 해설이 4개를 넘으면 기본 상태에서는 첫 4개 항목만 표시한다. 해설 상자 오른쪽의 원형 `▾` 아이콘으로 전체를 펼치고 `▴` 아이콘으로 다시 접는다. 관리자 화면에서는 펼치기·접기 아이콘을 `변환` 버튼 바로 오른쪽, 관리 버튼 중 마지막에 둔다.
- 접기·펼치기 아이콘에는 현재 상태에 맞는 `aria-expanded`, 접근성 이름과 툴팁을 둔다. 관리자 여부와 관계없이 읽기 전용 사용자도 사용할 수 있어야 한다.
- `편집`, `md 업로드`, `스크립트 요약`, `변환`은 관리자에게만 표시한다. 편집 상태에서는 해설 읽기 영역과 접기·펼치기 및 다른 관리 버튼을 숨긴다.
- 펼침 상태는 현재 화면 세션에서 화가별로 구분한다. 한 화가의 펼침 상태가 다른 화가의 해설을 자동으로 펼치지 않는다.
- 해설을 펼칠 때마다 현재 화가의 최신 작품 목록과 로컬 이미지 상태를 다시 대조하여 작품명 링크를 갱신한다. 처음 화면을 그린 뒤 이미지가 준비된 작품도 새 링크 검색 결과에 반영한다.
- 변환할 저장 입력 기록이 없으면 `변환할 해설 입력 기록이 없습니다.`라고 안내한다.

## 작품명 연결

- 해설에 현재 화가의 `works[]`에 등록된 작품명이 나오면 해당 글자를 작품 링크로 표시한다. 한글·영문·원어 제목의 정확한 표기와 `《 》`·`〈 〉` 안에서 문장부호만 다른 표기를 연결 대상으로 삼는다.
- 작품명 연결은 로컬 `artistId + workId` 관계를 사용한다. 외부 작품 URL을 새로 만들거나 다른 화가의 동명 작품으로 연결하지 않는다.
- 작품 링크를 눌러도 오른쪽 작품 설명 창이나 화면 분할을 열지 않는다. 기존 오른쪽 설명 창이 열려 있으면 닫고, 화면 중앙의 별도 이미지 박스에 해당 작품을 표시한다.
- 이미지 박스는 작품 비율을 바꾸거나 자르지 않는다. 가로·세로 중 먼저 한계에 닿는 긴 변이 현재 화면 가로 또는 세로의 40%가 되도록 자동 계산한다.
- 이미지 박스에는 닫기 아이콘을 두지 않는다. 박스 안 이미지를 더블클릭하면 닫고 접근성을 위해 `Esc` 키 닫기도 허용한다.
- 짧은 일반 명사와 작품명이 우연히 겹칠 수 있으므로 새 제목 대응 규칙을 추가할 때에는 긴 제목을 우선하고 겹치는 링크를 중복 생성하지 않는다.

## 구현 경계

- 화면 렌더링과 상호작용은 `app/app-artists.js`, 스타일은 `styles.css`, 링크·스크립트 저장은 `server-data.js`, 문서형 변환은 `server-artist-research.js`, API 진입점은 `server.js`가 소유한다.
- 데이터 정규화는 `data-contract.js`에서 스크립트와 링크 보조 필드를 보존한다. 일반 화가 저장이나 링크 순서 변경으로 스크립트가 사라지지 않아야 한다.
- 이 기능을 국가별 미술, 화가 리스트, 사조, 기법 및 용어, 주제·사건 탭의 설명 상자에 자동 적용하지 않는다.

## 검증

- 변경 후 `node --check app/app-artists.js`, `node --check server-artist-research.js`, `node --check server-data.js`, `node --check server.js`를 실행한다.
- `npm run research:check`로 URL 정규화, 이전 스크립트 필드 보존, 스크립트 요약 저장, 기존 내용 보존, 입력 순서 보존, 문서형 변환 저장 흐름을 검사한다.
- 공통 규칙의 기본 검사를 실행한다. 기존 이미지 누락처럼 이번 변경과 무관한 실패가 있으면 항목과 개수를 결과에 명시한다.
- 서버를 재시작한 뒤 `/api/access`, `app/app-artists.js`, `styles.css`가 정상 응답하고 공통 연표 코드에 특정 화가 ID 분기가 없는지 확인한다.
- 관리자와 읽기 전용 상태에서 각각 해설 4개 이하, 5개 이상, 작품명 포함, md 업로드, 스크립트 요약 저장, 변환 저장 사례를 확인한다.
